01 / רספונסיביות ו־Viewport

פיתוח אתרים
רספונסיביים

אתר רספונסיבי מתאים את הפריסה שלו לרוחב התצוגה. ביחידה זו נלמד להתאים רכיבים, תפריט, תמונות וטקסט בעזרת HTML, CSS ו־JavaScript.

RESPONSIVE LAYOUT● ● ●

שלושה כרטיסים בשורה בתצוגה רחבה ובעמודה בתצוגה צרה.

מטרות הלמידה

בסיום הלמידה תכירו מונחי בסיס בפיתוח אתרים רספונסיביים ותהיו מסוגלים לקרוא ולהבין CSS מתקדם.

הנחיות ללמידה

בכל פרק הסבר, דוגמה שניתנת לעריכה ושאלות לבדיקת הבנה. קראו את ההסברים וענו על השאלות. לאחר מכן נשוחח על החומר בכיתה.

מתי נדרשת התאמה לרוחב התצוגה?

פריסה שנראית תקינה בחלון רחב עלולה להיות צפופה בחלון צר: קישורים יכולים לחרוג מהשורה, תמונה יכולה לצאת מגבולות התוכן וכרטיסים יכולים להיות צרים מדי לקריאה. אתר רספונסיבי משנה את רוחבי הרכיבים ואת סידורם כדי שהתוכן יישאר קריא ושכל הפעולות יהיו זמינות. לא מסתפקים בהקטנת האתר כולו.

ההתאמה נדרשת גם כשמשנים את גודל חלון הדפדפן במחשב. לכן נבדוק את השטח הזמין לדף, ולא רק אם המשתמש נכנס מטלפון או ממחשב.

תפקידי HTML, CSS ו־JavaScript

HTML מגדיר את התוכן והמבנה, CSS את המראה והפריסה, ו־JavaScript את ההתנהגות. ברספונסיביות רוב העבודה היא ב־CSS; ניעזר ב־JavaScript רק כשהמשתמש מפעיל פעולה. כדי לייצר אתרים שניתן להשתמש בהם ברוחבי תצוגה שונים, אפשר לעבוד בשתי גישות:

רספונסיבי

פריסה גמישה

התוכן זורם בהתאם לשטח הזמין. ברוחבים מסוימים אפשר לשנות גם את המבנה, למשל משורה לעמודה.

אדפטיבי

פריסות מוגדרות מראש

בוחרים בין כמה פריסות מוכנות לפי תנאים. בפועל אפשר לשלב בין הגישות; כאן נתמקד בפריסה רספונסיבית.

היכן כותבים את הקוד?

באתר רגיל אפשר לשמור את המבנה בקובץ index.html, את העיצוב ב־styles.css ואת ההתנהגות ב־app.js. כדי שהדפדפן ישתמש בקובצי העיצוב וההתנהגות, צריך לקשר אליהם מתוך ה־HTML. בדוגמה הבאה שלושת הקבצים נמצאים באותה תיקייה:

<!doctype html>
<html lang="he" dir="rtl">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="styles.css">
  <script src="app.js" defer></script>
</head>
<body>
  <div class="box">תוכן לדוגמה</div>
</body>
</html>

<head> מכיל הגדרות וקישורים למשאבים; התוכן שמוצג למשתמש נמצא ב־<body>. המאפיין defer מאפשר לקוד JavaScript לפעול לאחר שמבנה ה־HTML נקרא, כך שאפשר יהיה למצוא את הרכיבים בקוד. אם קובץ נמצא בתיקייה אחרת, יש לעדכן את הנתיב אליו.

בכללי CSS מציינים תחילה בורר (Selector), כלומר על אילו רכיבים הכלל חל. למשל, .box בוחר רכיבים שקיבלו class="box". הנקודה נכתבת בבורר ב־CSS, ואינה חלק משם המחלקה ב־HTML. בתוך הסוגריים המסולסלים כותבים תכונות וערכים, כגון width: 100%;. הנקודתיים מפרידות בין התכונה לערך, והסימן נקודה ופסיק מסיים את ההגדרה.

השימוש בעורכי הקוד ביחידה. לשונית HTML מכילה את תוכן ה־body בלבד. תגית ה־viewport, ה־CSS וקוד ה־JavaScript מחוברים אוטומטית להדגמה. כתבו כל שפה בלשונית שלה ולחצו ״הרצת הקוד״ לאחר שינוי. שינוי בקרת הרוחב פועל מיד על התוצאה שכבר הורצה. ״איפוס הדוגמה״ מחזיר את הקוד המקורי; ״הורדת הקוד״ שומרת את שלוש הלשוניות במסמך HTML אחד.

הגדרת אזור התצוגה: Viewport

ה־viewport הוא אזור התצוגה של הדף בדפדפן. הוא עשוי להיות צר יותר מהמסך כולו. בטלפון, תגית זו ב־<head> מנחה את הדפדפן להשתמש ברוחב המכשיר ביחידות CSS, בקנה מידה התחלתי של 1:

<meta name="viewport" content="width=device-width, initial-scale=1">

התגית אינה הופכת את העיצוב לרספונסיבי בעצמה. צריך גם CSS מתאים. השאירו למשתמשים אפשרות להגדיל את הדף; אל תוסיפו user-scalable=no.

את התגית מוסיפים פעם אחת בתוך ה־<head> של כל עמוד HTML, ולא בקובץ CSS. width=device-width מנחה דפדפן נייד להתאים את אזור התצוגה לרוחב המכשיר בפיקסלי CSS; initial-scale=1 מגדיר את קנה המידה ההתחלתי. ללא הגדרה מתאימה, דפדפן נייד עשוי להשתמש באזור פריסה רחב ולהקטין את הדף כדי להכניסו למסך, כך שהטקסט ייראה קטן.

רוחב קבוע ורוחב גמיש

מיכל הוא רכיב שמכיל רכיבים אחרים. width: 600px קובע לרכיב רוחב של 600 פיקסלי CSS, גם כשהמיכל שלו צר יותר. width: 100% מתאים את הרוחב לרוחב המיכל. אפשר להוסיף max-width: 600px כדי שהרכיב יישאר גמיש, אך לא יגדל מעבר ל־600 פיקסלים.

.box {
  width: 100%;
  max-width: 600px;
}

אם רוחב המיכל הוא 300 פיקסלים, הרכיב בדוגמה יהיה ברוחב 300 פיקסלים. אם המיכל יתרחב ל־900 פיקסלים, הרכיב ייעצר ברוחב 600 פיקסלים. width מגדיר את הרוחב המבוקש, ו־max-width מציב לו גבול עליון. האחוזים כאן מתייחסים למיכל המכיל, שעשוי להיות צר מה־viewport.

ריווח ומסגרת כחלק מרוחב הרכיב

padding הוא הריווח הפנימי בין התוכן למסגרת, border היא המסגרת, ו־margin הוא הריווח מחוץ לרכיב. כברירת מחדל, רוחב CSS מתייחס לתוכן, ולכן padding ו־border יכולים להתווסף אליו ולגרום לחריגה גם כשכתבנו width: 100%.

* {
  box-sizing: border-box;
}

את הכלל הזה מוסיפים לקובץ ה־CSS. הכוכבית בוחרת את כל הרכיבים, ו־border-box גורם לחישוב הרוחב לכלול גם את הריווח הפנימי ואת המסגרת. ריווח חיצוני אינו נכלל בו. למשל, רכיב ברוחב 300 פיקסלים עם padding של 20 פיקסלים בכל צד יישאר ברוחב כולל של 300 פיקסלים; השטח שנותר לתוכן יקטן.

בהדגמות ההגדרה הזו כבר כלולה. גם לדף שבהדגמה יש ריווח פנימי, ולכן רוחב הקופסה יכול להיות קטן מרוחב הדף שבחרתם בבקרה.

הדגמה ותרגול

השוואת רוחב קבוע לרוחב גמיש

בחרו רוחב של 360 פיקסלים. הקופסה הראשונה קבועה ברוחב 600 פיקסלים; השנייה גמישה. איזו מהן תחרוג? לאחר מכן החליפו ב־CSS את width: 600px ב־width: 100% והריצו.

התוצאה הצפויה: ברוחב צר הקופסה הגמישה נשארת בתוך הדף, והקופסה הקבועה חורגת. אחרי שינוי הרוחב של .fixed ל־100%, גם היא תתאים למיכל. אם לא חל שינוי, ודאו שערכתם את הכלל של .fixed ולחצתם ״הרצת הקוד״.

02 / Flexbox

סידור רכיבים עם Flexbox

Flexbox הוא כלי CSS לסידור רכיבים בשורה או בעמודה. הגדרות המיכל משפיעות על הפריסה של הילדים הישירים שלו.

הגדרת המבנה ב־HTML והפעלת Flexbox ב־CSS

ראשית מזהים את הרכיב שמכיל את הפריטים שרוצים לסדר יחד. בדוגמה הבאה ה־ul הוא המיכל, ושלושת רכיבי ה־li שבתוכו הם הילדים הישירים. בכל פריט יש קישור a:

<ul class="links">
  <li><a href="#intro">מידע</a></li>
  <li><a href="#topics">נושאים</a></li>
  <li><a href="#contact">יצירת קשר</a></li>
</ul>

בקובץ ה־CSS בוחרים את המחלקה .links ומגדירים עליה display: flex. הגדרת Flexbox חלה על הפריסה של הילדים הישירים של המיכל, ואינה הופכת כל צאצא בתוכו לפריט Flex של אותו מיכל.

המיכל · Container

display: flex הופך את המיכל ל־Flex container. ‏flex-direction קובע את הכיוון. ‏gap מוסיף רווח.

הילדים הישירים · Items

אם ul הוא המיכל, רכיבי li הישירים שבתוכו הם הפריטים. הקישורים בתוך ה־li אינם פריטי Flex של אותו מיכל.

כיוון הפריסה ויישור הפריטים

justify-content מפזר פריטים לאורך הציר הראשי; align-items מיישר אותם בציר הניצב לו. ב־row הציר הראשי אופקי; ב־column הוא אנכי. בדף בעברית כיוון הכתיבה משפיע גם על תחילת השורה.

.links {
  display: flex;
  flex-direction: row;
  justify-content: flex-start;
  align-items: center;
  gap: 12px;
}
  • flex-direction: row מסדר את הפריטים בשורה; column מסדר אותם בעמודה. בדף עם dir="rtl", שורה רגילה מתחילה מימין.
  • justify-content: flex-start מצמיד את הפריטים לתחילת הציר הראשי; center מרכז אותם; space-between מחלק מקום פנוי בין הפריטים. כשאין מקום פנוי, לא יהיה מקום נוסף לחלוקה.
  • align-items: center ממרכז את הפריטים בציר הניצב. בשורה הוא מיישר אותם אנכית; בעמודה הוא מיישר אותם אופקית.
  • gap: 12px מוסיף רווח בין פריטים סמוכים. הוא אינו יוצר רווח בין המיכל לפריטים שבקצוות; לשם כך אפשר להשתמש ב־padding של המיכל.

מה קורה כשאין מספיק מקום בשורה?

ברירת המחדל של Flexbox היא לנסות להחזיק את הפריטים בשורה אחת. פריטים עשויים להצטמצם, אך תוכן ארוך עדיין יכול לגרום לחריגה. אם רוצים לאפשר מעבר של פריטים לשורה נוספת, מוסיפים למיכל flex-wrap: wrap;. לעומת זאת, flex-direction: column משנה את כיוון הפריסה כולה לעמודה.

.links {
  display: flex;
  flex-wrap: wrap;
  gap: 12px;
}

חלוקת המקום הפנוי עם flex-grow

לאחר הקצאת המקום הראשוני לפריטים, ייתכן שנותר במיכל מקום פנוי. flex-grow הוא מספר שקובע באיזה יחס תחולק התוספת בין הפריטים. פריט עם flex-grow: 4 יקבל פי ארבעה מהתוספת שיקבל פריט עם flex-grow: 1. זהו יחס בין התוספות, ולא בהכרח בין הרוחבים הכוללים של הפריטים.

לדוגמה, אם לשני פריטים גורמי גדילה 4 ו־1, ויש 100 פיקסלים פנויים לחלוקה, הראשון יקבל תוספת של 80 פיקסלים והשני תוספת של 20 פיקסלים. תוספת זו מתווספת לגודל הבסיס של כל פריט.

את flex-grow מגדירים על הפריטים, ולא על המיכל. הבורר .links > li בוחר רק את רכיבי ה־li שהם ילדים ישירים של המיכל. בתוספת :first-child בוחרים את הילד הראשון:

.links > li { flex-grow: 1; }
.links > li:first-child { flex-grow: 4; }

משמעות ההגדרה flex: 1 בהדגמות

flex היא תכונת קיצור שמחברת בין גדילה, כיווץ וגודל בסיס. ההגדרה flex: 1 מתפרשת בדפדפנים כ־flex: 1 1 0%: מותר לפריט לקבל מקום פנוי, מותר לו להתכווץ, וגודל הבסיס לחישוב הוא 0%. כשאותה הגדרה חלה על כמה כרטיסים בשורה, היא עוזרת להם לחלוק את המקום באופן שווה.

בהדגמת הכרטיסים מופיעה גם min-width: 0 על כל כרטיס. היא מאפשרת לו להצטמצם מתחת לרוחב המינימלי שהתוכן היה כופה עליו. אם יש טקסט ארוך ללא רווחים, אפשר להוסיף לטקסט overflow-wrap: anywhere כדי לאפשר שבירת שורה בתוכו.

הדגמה ותרגול

שינוי כיוון הפריסה ויישור הקישורים

  1. שנו flex-direction: row ל־column והריצו. מה קרה לקישורים?
  2. החזירו ל־row, שנו justify-content ל־space-between והריצו שוב.

התוצאה הצפויה: column מציג את הקישורים זה מתחת לזה. לאחר החזרה ל־row, space-between מפזר את המקום הפנוי ביניהם. את ההגדרות האלה משנים בכלל .links, משום שזהו המיכל. הגדרתן על קישור יחיד לא תסדר את שאר הקישורים.

תרגול נוסף: שינוי flex-grow

הוסיפו .links > li { flex-grow: 1; } וגם .links > li:first-child { flex-grow: 4; }. הפריט הראשון יקבל פי ארבעה מהתוספת של המקום הפנוי שכל פריט אחר מקבל. זו אינה הבטחה שרוחבו הכולל יהיה פי ארבעה, כי גם גודל הבסיס והתוכן משפיעים.

03 / Media Queries

שינוי פריסה עם Media Queries

Media Query מאפשר להפעיל כללי CSS רק כאשר תנאי מסוים מתקיים. כאן נשתמש בתנאי רוחב כדי להציג כרטיסים בעמודה בתצוגה צרה ובשורה בתצוגה רחבה.

כתיבת תנאי רוחב בקובץ CSS

כותבים Media Query באותו קובץ CSS שבו נכתבים שאר כללי העיצוב. השאילתה כוללת תנאי בסוגריים עגולים, ובתוך הסוגריים המסולסלים שלה כותבים כללי CSS רגילים: בורר, תכונה וערך. הדפדפן בודק את התנאי בעצמו בכל שינוי רוחב; אין צורך ב־JavaScript כדי להפעיל אותו.

  • min-width: 768px פירושו שהרוחב הוא לפחות 768 פיקסלי CSS.
  • max-width: 600px פירושו שהרוחב הוא לכל היותר 600 פיקסלי CSS.
  • התנאי מתייחס לרוחב ה־viewport של הדף. הוא אינו מגדיר רוחב קבוע לרכיב ואינו מזהה דגם מכשיר.

Mobile first: בסיס לתצוגה צרה והתאמות לתצוגה רחבה

כותבים קודם את כללי הבסיס למסך צר. אחריהם מוסיפים @media עם min-width כדי לשנות רק את מה שנחוץ במסך רחב. הכללים מחוץ לשאילתה ממשיכים לחול גם ברוחב גדול.

.cards { display: flex; flex-direction: column; }
@media (min-width: 768px) {
  .cards { flex-direction: row; }
}
נקודת שבירה (Breakpoint) היא הרוחב שבו משנים את העיצוב. min-width: 768px כולל גם 768 בדיוק; max-width: 600px כולל גם 600. בוחרים נקודות לפי צורכי התוכן, ולא כהבטחה לזיהוי טלפון או מחשב.

בדוגמה, עד רוחב 767 פיקסלים הכרטיסים מוצגים בעמודה. ברוחב 768 ומעלה מופעל הכלל שבתוך השאילתה, והכרטיסים מוצגים בשורה. שאר כללי הבסיס ממשיכים לחול.

איך הדפדפן מחבר את כללי הבסיס ואת השאילתה?

  1. הכלל שמחוץ ל־@media חל בכל רוחב. הוא מפעיל Flexbox ומגדיר כיוון של עמודה.
  2. כשהרוחב קטן מ־768, התנאי אינו מתקיים והדפדפן אינו מחיל את הכללים שבתוך השאילתה.
  3. כשהרוחב מגיע ל־768, הכלל שבתוך השאילתה נעשה פעיל. בשני הכללים מופיע אותו בורר, .cards, והכלל המאוחר משנה את flex-direction לשורה. אין צורך לכתוב שוב display: flex או את הריווחים שכבר הוגדרו בבסיס.

את כללי השאילתה כותבים אחרי כללי הבסיס. כשכמה כללים חלים על אותו רכיב, סדר הכתיבה משפיע אם לבוררים אותה ספציפיות, כלומר אותה דרגת עדיפות. בהדגמה הבורר זהה בשני המקומות, ולכן הכלל המאוחר קובע את הכיוון.

בחירת נקודת שבירה לפי התוכן

768 פיקסלים הם בחירה לדוגמה. בפרויקט מתחילים בפריסה הצרה ומרחיבים בהדרגה את החלון. כאשר יש מספיק מקום להציג את הכרטיסים בשורה באופן קריא, אפשר להגדיר שם נקודת שבירה. אין חובה להשתמש באותה נקודת שבירה בכל אתר או ליצור כלל לכל דגם טלפון.

המספרים מוצגים כאן ברוחבים שלמים כדי להקל על הבדיקה. התנאי עצמו הוא ״לפחות 768״: גם רוחב קטן במעט מ־768 עדיין אינו מפעיל אותו.

הדגמה ותרגול

בדיקת הפריסה לפני נקודת השבירה ואחריה

בחרו 767 ואז 768 בבקרת הרוחב. הסתכלו גם על הכרטיסים וגם על הודעת מצב השאילתה. אחר כך שנו בקוד את 768 ל־900 והריצו; כעת בדקו ב־899 וב־900.

התוצאה הצפויה: בקוד המקורי המעבר מעמודה לשורה קורה ב־768. אחרי החלפת התנאי ל־900 והרצה, הוא יקרה ב־900. הודעת המצב שבהדגמה מסמנת אם השאילתה פעילה. אם כיוון הפריסה אינו משתנה, בדקו שהכלל נמצא בתוך הסוגריים המסולסלים של השאילתה ושהמספר כולל יחידת px.

הסבר התחביר של Media Query

@media פותח תנאי. הסוגריים העגולים מכילים את התנאי; בתוך הסוגריים המסולסלים כותבים כללי CSS רגילים. השאילתה נבדקת מול רוחב התצוגה של הדף שבהדגמה, ולא מול רוחב כל יחידת הלמידה.

04 / תפריט רספונסיבי

תפריט רספונסיבי עם CSS ו־JavaScript

ברוחב צר נציג כפתור לפתיחת התפריט. ברוחב רחב הקישורים יופיעו בשורה, בלי צורך בכפתור.

חלוקת התפקידים בקוד התפריט

  1. HTML: רכיב button ואזור ניווט בעל מזהה. aria-controls מחבר ביניהם; aria-expanded מתאר אם התפריט פתוח.
  2. CSS: במצב צר מסתירים את הקישורים עד לפתיחה. מ־768 פיקסלים מציגים אותם תמיד ומסתירים את הכפתור.
  3. JavaScript: לחיצה מחליפה מצב, מעדכנת מחלקה וגם את aria-expanded.

מבנה הכפתור והניווט ב־HTML

מוסיפים כפתור button ורכיב nav עם הקישורים. לכל אחד מזהה id ייחודי, כדי שנוכל לבחור אותו ב־CSS וב־JavaScript. בורר שמתחיל ב־# מתייחס למזהה: #main-nav בוחר את הרכיב עם id="main-nav". להבדיל ממחלקה, מזהה אמור להופיע פעם אחת בלבד בעמוד.

<button id="nav-button" type="button"
  aria-controls="main-nav" aria-expanded="false" hidden>
  תפריט
</button>
<nav id="main-nav" aria-label="תפריט הסדנאות">
  <a href="#about">על הסדנאות</a>
  <a href="#workshops">הסדנאות</a>
</nav>

type="button" מגדיר כפתור פעולה, שאינו כפתור שליחת טופס. כפתור HTML רגיל כבר תומך בהפעלה באמצעות Enter או Space, ו־aria-label נותן לאזור הניווט שם שקורא מסך יכול להקריא. המאפיין hidden מסתיר בתחילה את הכפתור; קוד ה־JavaScript מסיר אותו לאחר שהגדיר את פעולת הפתיחה.

הצגה והסתרה באמצעות מחלקות CSS

לאחר הכנת הכפתור, הקוד מוסיף ל־html את המחלקה nav-ready. בתצוגה צרה, הכלל .nav-ready #main-nav מסתיר את הקישורים באמצעות display: none. כשהניווט מקבל גם את המחלקה is-open, כלל נוסף מציג אותו:

.nav-ready #nav-button { display: block; }
.nav-ready #main-nav { display: none; flex-direction: column; }
.nav-ready #main-nav.is-open { display: flex; }
@media (min-width: 768px) {
  .nav-ready #main-nav {
    display: flex;
    flex-direction: row;
  }
  .nav-ready #nav-button { display: none; }
}

#main-nav.is-open פירושו ״הרכיב בעל המזהה main-nav שגם נושא את המחלקה is-open״. הרווח אחרי .nav-ready מציין שהרכיב נמצא בתוך רכיב עם מחלקה זו. display: none מסיר את הקישורים מהתצוגה ומסדר המעבר באמצעות Tab; שינוי ל־display: flex מציג אותם ומסדר אותם שוב.

ברוחב 768 ומעלה, Media Query מציג את הניווט בשורה גם כשהמחלקה is-open אינה קיימת, ומסתיר את הכפתור. לפני ש־JavaScript פועל, הקישורים נשארים גלויים כדי שלא לחסום את הניווט.

ציון מצב התפריט עבור טכנולוגיות מסייעות

לכפתור מוגדר המאפיין aria-controls="main-nav", שמפנה למזהה הניווט שעליו הוא שולט. המאפיין aria-expanded מתאר את מצב הפתיחה: false כשהתפריט סגור, ו־true כשהוא פתוח. כך קורא מסך יכול להודיע למשתמש אם התפריט פתוח או סגור.

בעת לחיצה, ה־JavaScript מעדכן שני דברים: את המחלקה is-open, שקובעת אם הקישורים מוצגים בתצוגה צרה, ואת הערך של aria-expanded בכפתור. בפתיחה מוסיפים את המחלקה ומגדירים true; בסגירה מסירים את המחלקה ומגדירים false.

קריאת קוד ה־JavaScript של הפתיחה והסגירה

הקוד מוצא את הכפתור ואת הניווט באמצעות document.querySelector, שמחזיר את הרכיב הראשון המתאים לבורר. המשתנים button ו־nav שומרים הפניות לרכיבים האלה:

const button = document.querySelector('#nav-button');
const nav = document.querySelector('#main-nav');

function setOpen(open) {
  nav.classList.toggle('is-open', open);
  button.setAttribute('aria-expanded', String(open));
}
button.addEventListener('click', () => {
  setOpen(button.getAttribute('aria-expanded') !== 'true');
});
button.hidden = false;
document.documentElement.classList.add('nav-ready');
  • הפונקציה setOpen מקבלת ערך בוליאני: true לפתיחה או false לסגירה.
  • classList.toggle('is-open', open) מוסיף את המחלקה כאשר open הוא true, ומסיר אותה כאשר הוא false. זו המחלקה שכללי ה־CSS בודקים.
  • setAttribute מעדכן מאפיין HTML. ‏String(open) ממיר את הערך הבוליאני לטקסט 'true' או 'false' עבור המאפיין aria-expanded.
  • addEventListener('click', ...) מגדיר מה יקרה בלחיצה. הביטוי !== 'true' בודק אם התפריט אינו פתוח כרגע: אם התפריט סגור, נפתח אותו; אם הוא פתוח, נסגור אותו.

שתי השורות האחרונות משלימות את ההכנה: button.hidden = false מסיר את ההסתרה הראשונית של הכפתור, ו־document.documentElement הוא רכיב html, שעליו מוסיפים את המחלקה nav-ready. כך כללי ההסתרה ב־CSS נכנסים לתוקף רק אחרי שהכפתור מסוגל להגיב ללחיצה.

בקוד המלא מופיעה גם window.matchMedia('(min-width: 768px)'). היא מאפשרת ל־JavaScript לבדוק את אותו תנאי רוחב, באמצעות הערך matches, ולטפל באירוע change כאשר התנאי משתנה. בהדגמה היא משמשת לאיפוס מצב הפתיחה במעבר בין תצוגה צרה לרחבה. אם משנים את נקודת השבירה, מעדכנים את המספר גם ב־CSS וגם ב־JavaScript.

סגירה עם Escape מחזירה את המיקוד לכפתור, כדי שהמשתמש יוכל להמשיך לנווט מהמקום שבו פתח את התפריט. גם שינוי רוחב מטופל כך שהמיקוד לא יישאר על רכיב שנעשה מוסתר.

הדגמה ותרגול

בדיקת התפריט בתצוגה צרה ורחבה

בחרו 360, לחצו על ״תפריט״ בתוך ההדגמה, ואז בדקו גם עם המקלדת: Tab למעבר, Enter לפתיחה ו־Escape לסגירה. עברו ל־1024 וחזרו ל־360: התפריט חוזר למצב סגור. בלשונית JS מצאו את השורה שמעדכנת aria-expanded.

התוצאה הצפויה: בתצוגה צרה הכפתור מציג או מסתיר את הקישורים בכל לחיצה; בתצוגה רחבה הקישורים תמיד גלויים והכפתור מוסתר. אם לחיצה אינה משנה דבר, ודאו שהמזהים ב־HTML תואמים לבוררים ב־JavaScript ושמחלקת is-open נכתבת באותו אופן ב־CSS וב־JavaScript.

שמירה על גישה לקישורים. כאן מסתירים קישורים רק כאשר יש דרך לפתוח אותם. אין להעלים תוכן חיוני בנייד בלי להציע אליו גישה. סדר הקישורים ב־HTML נשמר גם כשהפריסה משתנה.

05 / תמונות רספונסיביות

התאמת תמונות לרוחב המיכל

תמונה ברוחב טבעי גדול עלולה להרחיב את התוכן מעבר למיכל. שתי הגדרות קצרות שומרות אותה בתוך הגבולות.

הוספת תמונה והגדרת המיכל שלה

ב־HTML מוסיפים רכיב img. המאפיין src מציין את הנתיב לקובץ התמונה, ו־alt מספק תיאור חלופי של המידע שבתמונה. אם התמונה נמצאת בתוך כרטיס או בתוך figure, הרכיב שמכיל אותה קובע את השטח הזמין לה.

<figure>
  <img src="images/campus.jpg"
    width="900" height="400"
    alt="בניין הקמפוס והרחבה שלפניו">
  <figcaption>הקמפוס</figcaption>
</figure>

בדוגמה זו יש להחליף את ערך המאפיין src בנתיב לקובץ תמונה שקיים באתר. figure מקבץ את התמונה ואת הכיתוב, ו־figcaption הוא הכיתוב המוצג לידה. המאפיינים width ו־height מציינים את ממדי התמונה ומאפשרים לדפדפן להקצות מקום ביחס המתאים עוד לפני טעינתה. כללי CSS עדיין יכולים להתאים את גודלה בפועל.

הגבלת רוחב התמונה עם max-width

img {
  max-width: 100%;
  height: auto;
}

max-width: 100% מגביל את הרוחב המרבי של התמונה לרוחב המיכל. אם התמונה גדולה מהמיכל, היא תוקטן כדי להיכנס אליו. אם היא קטנה ממנו ולא נקבע לה רוחב נוסף, היא יכולה להישאר בגודלה המקורי. לדוגמה, תמונה ברוחב טבעי של 200 פיקסלים במיכל של 500 פיקסלים לא תוגדל רק בגלל הגדרה זו.

את הכלל כותבים בקובץ CSS. הבורר img מחיל אותו על כל התמונות בעמוד; אם רוצים להחיל אותו רק על תמונות בכרטיסים, אפשר לכתוב .card img ולתת למיכל את המחלקה card. לעומת max-width: 100%, ההגדרה width: 100% מבקשת למלא את רוחב המיכל גם אם הדבר יגדיל תמונה קטנה ועלול לפגוע בחדותה.

שמירה על יחס הממדים עם height: auto

height: auto מתאים את גובה התמונה לרוחב שלה ושומר על היחס בין הרוחב לגובה. לדוגמה, תמונה בגודל 900×400 שתוקטן לרוחב של 450 פיקסלים תהיה בגובה 200 פיקסלים. גובה CSS קבוע של 400 פיקסלים במצב הזה היה מעוות את התמונה.

השינוי נוגע לתצוגה בדפדפן: קובץ התמונה עצמו אינו משתנה. בהדגמה מוגדרת לתמונה גם התכונה display: block, כדי להציג אותה כרכיב בלוק ולמנוע את הרווח הקטן שיכול להופיע מתחת לתמונה כשהיא מוצגת כחלק משורת טקסט.

הדגמה ותרגול

בדיקת תמונה עם הגבלת רוחב ובלעדיה

ברוחב 360 התמונה נכנסת למסגרת. שנו את max-width ל־none, הריצו וגללו בתוך ההדגמה כדי לראות את החריגה. החזירו ל־100%. מה נפתר בלי לשנות את קובץ התמונה?

התוצאה הצפויה: הערך none מסיר את הגבלת הרוחב המרבי, והתמונה הרחבה חורגת מהמיכל. החזרת 100% מתקנת את החריגה; הגובה משתנה יחד עם הרוחב בגלל height: auto. התמונה כבר כלולה בקוד ההדגמה, ואין צורך לשנות את src כדי לבדוק את כללי הגודל.

התאמת סרטון מקומי

אותו עיקרון מתאים גם לרכיב video שמציג קובץ וידאו באתר. מגבילים את הרוחב ומשאירים את הגובה אוטומטי כדי לשמור על יחס הממדים:

video {
  max-width: 100%;
  height: auto;
}

הקטנת רוחב התצוגה אינה מפחיתה את גודל הקובץ שהדפדפן מוריד. לכן, בנוסף להתאמת הפריסה, כדאי להשתמש בקובצי תמונה ווידאו בגודל מתאים לצורכי האתר.

06 / טקסט ויחידות מידה

גודל טקסט ויחידות מידה

יחידות מידה ב־CSS קובעות כיצד מחושבים גדלים. חלקן מבוססות על גודל גופן, אחרות על המיכל או על אזור התצוגה.

חישוב גודל טקסט עם rem

רכיב השורש של המסמך הוא html. יחידת rem מתייחסת לגודל הגופן שמוגדר בו. אם גודל הגופן בשורש הוא 16 פיקסלים, 1rem שווה ל־16 פיקסלים ו־2rem ל־32. אם נשנה את גודל הגופן בשורש ל־20 פיקסלים, 2rem יהיו 40 פיקסלים.

היכן ואיך מגדירים את גודל הבסיס של rem?

מגדירים את גודל הבסיס באמצעות התכונה font-size בכלל שהבורר שלו הוא html בקובץ ה־CSS שמקושר לאתר. אפשר לכתוב את אותם כללים גם בתוך תגית <style> ב־head, אך באתר עם כמה עמודים נוח לשמור אותם בקובץ עיצוב משותף.

/* בקובץ styles.css */
html {
  font-size: 16px;
}
h1 {
  font-size: 2rem;
}
p {
  font-size: 1rem;
}

כאן הבסיס הוא 16 פיקסלים. גודל הכותרת יהיה 32 פיקסלים וגודל הפסקה 16 פיקסלים. אם נשנה רק את השורה ב־html ל־font-size: 20px, הכותרת תהיה 40 פיקסלים והפסקה 20 פיקסלים. לא צריך לשנות את הערכים 2rem ו־1rem בכל רכיב בנפרד.

הבסיס נקבע ב־html, ולא ב־body. אם גודל הגופן ב־html הוא 16px ול־body הוגדר font-size: 20px, ערך של 1rem עדיין שווה ל־16px. טקסט שאינו מקבל הגדרת גודל משלו יכול לרשת את גודל ה־body, אך חישוב rem ממשיך להשתמש בשורש.

שימוש בהעדפת גודל הגופן של המשתמש

אם לא מגדירים גודל גופן ב־html, הדפדפן משתמש בגודל הבסיס שלו, שבדרך כלל הוא 16 פיקסלים, אך המשתמש יכול לשנות אותו. דרך מקובלת לשמור על ההעדפה הזו היא לכתוב:

html {
  font-size: 100%;
}

במקרה הזה 100% מתייחס לגודל גופן הבסיס של הדפדפן. אם המשתמש בחר 20 פיקסלים, 1rem יהיה 20 פיקסלים ו־2rem יהיו 40 פיקסלים. בהדגמה נקבע בסיס מפורש של 16px כדי שאפשר יהיה לבצע את החישוב ולשנות אותו באופן מבוקר.

שימוש ב־rem גם לריווח

אפשר להשתמש ב־rem גם ב־padding, ב־margin ובמידות אחרות. כך אפשר לקשור את המרווחים לגודל גופן הבסיס:

.card {
  padding: 1rem;
  margin-block-start: 0.5rem;
}

בבסיס של 16px, הריווח הפנימי יהיה 16 פיקסלים והמרווח שמעל הכרטיס 8 פיקסלים. בבסיס של 20px הם יהיו 20 ו־10 פיקסלים. margin-block-start מציין מרווח בתחילת כיוון הבלוק, שבכתיבה האופקית של הדף הוא המרווח העליון.

ההבדל בין em לבין rem

בהגדרת font-size, היחידה em מתייחסת לגודל הגופן שהרכיב יורש מההורה שלו. למשל, אם גודל הגופן בהורה הוא 20px, אז font-size: 1.5em על הילד ייתן 30px. בתכונה כמו padding, היחידה em מתייחסת לגודל הגופן של הרכיב עצמו; לכן padding: 1em על אותו ילד יהיה 30 פיקסלים.

לעומת זאת, rem מתייחס תמיד לגודל הגופן בשורש, גם כאשר הרכיב נמצא בתוך רכיבים נוספים. הוא מתאים כשרוצים בסיס אחיד לחישוב בכל האתר. em יכול להתאים כשמרווח צריך להשתנות עם גודל הגופן של רכיב מסוים, למשל הריווח הפנימי בכפתור.

יחידות מידה נפוצות

משמעות יחידות המידה ודוגמאות לשימוש
יחידה ביחס למה? דוגמה
px פיקסל CSS, שאינו בהכרח פיקסל פיזי יחיד במסך border: 1px solid
rem גודל הגופן של רכיב השורש html אם השורש 16px, אז 2rem הם 32px
em ב־font-size: גודל הגופן שהתקבל בירושה. בתכונות כמו padding: גודל הגופן של הרכיב עצמו padding של 1em ברכיב עם גופן 20px הוא 20px
% תלוי בתכונה; ב־width, בדרך כלל רוחב המיכל המכיל width: 80%
vw / vh 1vw הוא 1% מרוחב ה־viewport; ‏1vh הוא 1% מגובהו width: 80vw

ההבדל בין אחוזים לבין יחידות אזור התצוגה

ב־width: 50% הבסיס הוא רוחב המיכל המכיל. אם רוחב המיכל 400 פיקסלים, רוחב הרכיב יהיה 200 פיקסלים. לעומת זאת, width: 50vw מתייחס למחצית רוחב ה־viewport של הדף: אם רוחב התצוגה הוא 1000 פיקסלים, נקבל 500 פיקסלים גם כשהמיכל צר יותר.

1vh הוא 1% מגובה אזור התצוגה. יחידות vw ו־vh מתאימות כאשר רוצים לקשור מידה לאזור התצוגה, ואילו אחוזי רוחב מתאימים לרכיב שצריך להתאים למיכל שלו. לטקסט ביחידה זו נשתמש ב־rem, כדי לקשור את גודל הגופן לבסיס קריא ולא רק לרוחב החלון.

שינוי גודל טקסט בנקודת שבירה

rem אינו משתנה אוטומטית כאשר החלון מתרחב. כדי שכותרת תגדל בתצוגה רחבה, אפשר לשנות את ערך ה־rem שלה בתוך Media Query, תוך השארת גודל הבסיס:

html { font-size: 100%; }
h1 { font-size: 2rem; }
@media (min-width: 768px) {
  h1 { font-size: 2.5rem; }
}

כאשר הבסיס הוא 16 פיקסלים, הכותרת תהיה 32 פיקסלים בתצוגה צרה ו־40 פיקסלים מ־768 ומעלה. אפשר גם לשנות את גודל הגופן של html בתוך שאילתה, אבל אז כל הגדלים שמוגדרים ב־rem ישתנו יחד, כולל ריווחים. לכן בוחרים אם השינוי נדרש לרכיב מסוים או לכל האתר.

הדגמה ותרגול

השפעת גודל הגופן בשורש על רכיבים שמוגדרים ב־rem

  1. פתחו את לשונית CSS ומצאו את הכלל html { font-size: 16px; }.
  2. שנו רק את 16px ל־20px ולחצו ״הרצת הקוד״. הכותרת מוגדרת כ־2rem והפסקה כ־1rem.
  3. השוו את הכותרת, הפסקה והריווח לתווית שמוגדרת בגודל קבוע של 16px.
  4. החזירו את הבסיס ל־16px והריצו שוב כדי להשוות למצב המקורי.

התוצאה הצפויה: בבסיס של 20px הכותרת היא 40px, הפסקה 20px והריווח הפנימי של הקופסה 20px. התווית נשארת 16px כי אינה מוגדרת ב־rem. לכל הדגמה יש מסמך HTML נפרד, ולכן שינוי html בעורך משפיע רק על ההדגמה, ולא על גודל הטקסט של יחידת הלמידה.

הקשר בין יחידות מידה לרוחב התצוגה. ‏rem תלוי בגודל הגופן בשורש, ולא ישירות ברוחב התצוגה. אפשר לשנות את גודל הגופן בשורש באמצעות Media Query. בממשק אמיתי כדאי לכבד גם העדפות גופן של המשתמש, למשל באמצעות html { font-size: 100%; }, ולבדוק הגדלה ושבירת שורות.
